# Agent 长期记忆分层架构

## 概览

长期记忆系统的目标不是无限保存对话，而是让 Agent 在跨会话工作时能够保留当前状态、召回相关经验、沉淀稳定知识，并持续清理过时内容。来源文档采用分层设计，将会话热状态、向量召回、永久决策、人类可读知识和自动事实提取分别交给不同存储层。

## 核心机制

| 层级 | 角色 | 典型载体 | 主要职责 |
|---|---|---|---|
| 热状态 | 当前执行上下文 | `SESSION-STATE.md` | 在压缩或中断前保存任务状态 |
| 温存储 | 语义召回 | LanceDB 与本地 Embedding | 按相似度检索相关片段 |
| 冷存储 | 永久决策 | Git Notes | 保存分支相关、低频但重要的决策 |
| 精炼层 | 人类可读知识 | `MEMORY.md` 与日期日志 | 将经验压缩为可维护的长期资产 |
| 自动提取 | 事实识别 | Mem0 | 从对话中提取候选事实，降低手工触发成本 |

### 写前日志

热状态层采用“先写后响应”的 WAL 思路：在输出容易改变任务走向的重要回复前，先更新当前状态。它解决的是会话连续性，而不是知识检索，因此不应被当作永久知识库。

### 召回与精炼分离

向量库保存可搜索片段，精炼层保存经过筛选的规则、决策和稳定事实。前者追求召回率，后者追求可解释性与低噪声；两者混为一体会导致重复、冲突和上下文污染。

### 自动提取与维护循环

自动提取层负责发现候选记忆，定时任务负责索引优化、过期清理、分层迁移和备份。错误记录还可以进入学习目录，经复盘后形成新的规则或技能，从而构成“执行、记录、复盘、改进”的闭环。

## 实践要点

- 为每层定义明确的写入条件、生命周期和权威性，避免同一事实无差别复制。
- 重要决策进入精炼层前应保留来源、时间和适用范围，便于后续修订。
- 自动提取只能生成候选记忆；涉及身份、偏好和长期规则时应允许人工审核与删除。
- 定期评估召回质量，不要只关注索引是否成功；错误召回同样会降低 Agent 可靠性。
- 备份应覆盖人类可读文件、向量索引配置和恢复步骤，而不是只复制数据库文件。

## 决策依据

小型个人 Agent 可以先建立热状态与精炼层，再按检索需求增加向量库。只有当对话规模足以造成明显人工整理负担时，才值得引入自动事实提取。分层的价值在于降低耦合：任何单层失效都不应导致全部记忆不可用。

## 限制与边界

来源文档中的组件状态并不一致：部分层已配置，Mem0、定时维护和自我改进仍属于待完善方案。实现时还需单独处理隐私、删除权、冲突合并、Embedding 漂移和备份恢复验证。
